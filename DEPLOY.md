# Размещение на хостинге

## Требования

PHP 8.1 или новее с расширениями `pdo_sqlite`, `sodium`, `mbstring`. Сервер Apache или Nginx.

## Шаги

1. **Загрузите файлы.** Наружу должна смотреть только папка `public`.
   - Если в панели хостинга можно выбрать корневую папку сайта — загрузите проект целиком и укажите корнем `public`.
   - Если корень задан жёстко (`public_html`), положите содержимое `public` в `public_html`,
     а папки `config`, `database`, `logs`, `src` и файл `install.php` — на уровень выше, рядом с `public_html`.
   - Если служебные папки всё же оказались внутри корня, их закрывают файлы `.htaccess` (только для Apache).

2. **Установите базу.**
   - Есть SSH: `php install.php` в папке проекта.
   - Нет SSH: выполните установку на своём компьютере и загрузите **вместе** `config/config.php`
     и `database/clinic.sqlite`. Ключи и база должны быть из одной установки.

3. **Выдайте права на запись** веб-серверу для папок `database` и `logs` (обычно 755 или 775).
   SQLite создаёт рядом с базой временные файлы, поэтому права нужны на папку, а не только на файл.

4. **Включите HTTPS** (бесплатный сертификат Let's Encrypt в панели хостинга), затем
   раскомментируйте в `public/.htaccess` перенаправление на HTTPS и заголовок `Strict-Transport-Security`.

5. **Проверьте `config/config.php`:** `'debug' => false`.

6. **Проверьте защиту:** адреса `https://ваш-сайт/config/config.php`, `/src/db.php`,
   `/database/clinic.sqlite` не должны открываться.

## Резервное копирование

Регулярно скачивайте `database/clinic.sqlite` и храните отдельно копию `config/config.php`.
Без ключей из `config.php` резервная копия базы не расшифровывается.

## Nginx

Файлы `.htaccess` в Nginx не работают. Корнем сайта обязательно должна быть папка `public`,
а запрет доступа к скрытым файлам задаётся в конфигурации сервера:

```nginx
location ~ /\. { deny all; }
```
